Endpoint data collection consent
Version 2026-11-04.1

Purpose and timing
Collect read-only endpoint inventory and security posture for this organisation. Selected supported checks run after an agent enrolls and its asset is authorised, then periodically (default every 15 minutes; configurable by the operator), and when an authorised user requests a refresh. Every named osquery check requires explicit approval of this current document. Enrollment alone does not grant testing or collection permission. Supported queries are preselected in the approval dialog; the administrator can remove any before accepting. High-sensitivity checks and official packs require settings-management permission. Pinned osquery artifacts exist for Linux amd64 and for macOS (Intel and Apple Silicon); macOS support is experimental and only the checks marked for macOS run there. Windows is not supported yet.

Data read
The selected check or pack lists the exact tables and columns before approval. Depending on that selection, data can include operating system, kernel, hardware, hostname, installed packages and versions, local account and group names, listening ports and process names, firewall or hardening settings, and network interfaces, addresses and routes. Reported networks are proposals, not permission to scan; an administrator must approve bounded ranges separately. Browser history/extensions, private SSH keys, process arguments/environment and user-file contents are excluded. Pack queries not approved for this release stay skipped. Queries needing more privileges are skipped with an explicit reason when the agent lacks them.

Storage, reports and access
The server treats agent data as untrusted, keeps only known columns, redacts credential-shaped text, limits cells and rows, and bounds each sanitized dataset to 1 MiB. Free-form output and agent-supplied findings/logs are discarded for osquery. The latest successful dataset is stored separately from findings; a failed attempt preserves that earlier dataset and records the failure. Users with asset-read permission can see endpoint rows and mapped summaries. Findings and report exports follow their own permissions. Administrators and authorised infrastructure operators can also access their managed storage and backups. Only approved mapping rules produce report findings and posture summaries. This approval does not enable an external AI provider.

Retention
The server keeps only the latest successful dataset, until replacement, explicit deletion, or scheduled age-based expiry (default 30 days after server-recorded successful collection). Failed attempts do not extend that lifetime. An administrator can change retention from 1 to 3,650 days; there is no collection history. Findings (default 180 days after last observation), scan results (90 days after completion), frozen PDF/JSON reports (180 days after creation), and audit events (365 days, minimum 90) have separate policies. Scheduled cleanup removes application records and queues exact MinIO and Elasticsearch artifacts for durable deletion, retrying after outages or restart. Deleting an organisation removes its agents and related data; deletion is not complete in external storage while cleanup remains pending. Existing encrypted backups retain their copies until those backups expire. Deleting a latest endpoint dataset alone does not delete findings, reports, audit events or backups. Do not approve collection if the configured retention and backup lifetimes do not meet the organisation’s policy.

Stop and delete
Turn off a named check or pack on the agent/endpoint's collection settings in the organisation to stop new collections of those named queries. In-flight results are discarded after approval changes. To stop every action on an endpoint, revoke its testing authorisation or revoke the agent; legacy basic agent actions have separate testing permission. An administrator with asset-write and settings-management permission can use Delete collected data on the asset's Endpoint data tab. That deletes the latest datasets for the asset and invalidates in-flight results, without deleting findings, audit events, reports or backup copies. Deletion does not disable queued or future periodic or manually requested checks; turn them off or revoke testing permission before deletion to prevent recollection. Uninstall the agent if it should no longer contact the server.

Approval record
Approving records the administrator's identity, server time, document version and SHA-256, along with the selected query/pack, tables and frozen pack version. A changed document requires renewed approval for checks that need explicit consent. Revocation is recorded separately in the audit log. This is an operational collection permission, not a substitute for the organisation's legal basis or endpoint-owner agreement.

Persetujuan pengumpulan data endpoint
Versi 2026-11-04.1

Tujuan dan waktu
Kumpulkan inventaris endpoint dan postur keamanan organisasi ini secara baca-saja. Pemeriksaan terpilih yang didukung berjalan setelah agent terdaftar dan asetnya diizinkan untuk diuji, lalu secara berkala (default setiap 15 menit; dapat diatur operator), dan saat pengguna berizin meminta penyegaran. Setiap pemeriksaan osquery bernama memerlukan persetujuan eksplisit atas dokumen yang berlaku ini. Pendaftaran saja tidak memberikan izin pengujian atau pengumpulan. Kueri yang didukung dipilih sebelumnya dalam dialog persetujuan; administrator dapat membatalkan pilihan sebelum menerima. Pemeriksaan sensitif dan pack resmi memerlukan izin pengelolaan pengaturan. Artefak osquery yang dipatok tersedia untuk Linux amd64 dan macOS (Intel dan Apple Silicon); dukungan macOS masih eksperimental dan hanya pemeriksaan yang ditandai untuk macOS yang berjalan di sana. Windows belum didukung.

Data yang dibaca
Pemeriksaan atau pack terpilih mencantumkan tabel dan kolom yang tepat sebelum persetujuan. Tergantung pilihan, data dapat mencakup sistem operasi, kernel, perangkat keras, hostname, paket dan versi terpasang, nama akun dan grup lokal, port yang mendengarkan dan nama proses, pengaturan firewall atau penguatan, serta antarmuka, alamat, dan rute jaringan. Jaringan yang dilaporkan merupakan usulan, bukan izin scan; administrator harus menyetujui rentang terbatas secara terpisah. Riwayat/ekstensi browser, kunci SSH privat, argumen/lingkungan proses, dan isi berkas pengguna tidak disertakan. Kueri pack yang belum disetujui untuk rilis ini tetap dilewati. Kueri yang membutuhkan hak lebih tinggi dilewati dengan alasan eksplisit jika agent tidak memilikinya.

Penyimpanan, laporan, dan akses
Server memperlakukan data agent sebagai data tak tepercaya, hanya menyimpan kolom yang dikenal, menyunting teks menyerupai kredensial untuk menghapus data sensitif, membatasi sel dan baris, serta membatasi setiap dataset tersanitasi hingga 1 MiB. Keluaran bebas serta temuan/log yang diberikan agent dibuang untuk osquery. Dataset sukses terbaru disimpan terpisah dari temuan; percobaan gagal mempertahankan dataset sebelumnya dan mencatat kegagalan. Pengguna dengan izin baca aset dapat melihat baris endpoint dan ringkasan pemetaan. Temuan dan ekspor laporan mengikuti izinnya masing-masing. Administrator dan operator infrastruktur berizin juga dapat mengakses penyimpanan dan cadangan yang dikelolanya. Hanya aturan pemetaan yang disetujui menghasilkan temuan laporan dan ringkasan postur. Persetujuan ini tidak mengaktifkan penyedia AI eksternal.

Retensi
Server hanya menyimpan dataset sukses terbaru sampai diganti, dihapus secara eksplisit, atau kedaluwarsa menurut umur terjadwal (default 30 hari setelah pengumpulan sukses yang dicatat server). Percobaan gagal tidak memperpanjang masa simpan. Administrator dapat mengubah retensi dari 1 hingga 3.650 hari; tidak ada riwayat pengumpulan. Temuan (default 180 hari setelah pengamatan terakhir), hasil scan (90 hari setelah selesai), laporan PDF/JSON beku (180 hari setelah dibuat), dan audit (365 hari, minimum 90) memiliki kebijakan terpisah. Pembersihan terjadwal menghapus data aplikasi dan mengantrekan artefak MinIO dan Elasticsearch yang tepat untuk penghapusan persisten, dengan percobaan ulang setelah gangguan atau restart. Menghapus organisasi menghapus agent dan data terkaitnya; penghapusan di penyimpanan eksternal belum selesai selama pembersihan tertunda. Cadangan terenkripsi yang ada menyimpan salinannya sampai kedaluwarsa. Menghapus dataset endpoint terbaru saja tidak menghapus temuan, laporan, audit, atau cadangan. Jangan setujui pengumpulan jika retensi dan masa simpan cadangan yang dikonfigurasi tidak memenuhi kebijakan organisasi.

Menghentikan dan menghapus
Nonaktifkan pemeriksaan atau pack bernama pada pengaturan pengumpulan agent/endpoint di organisasi untuk menghentikan pengumpulan baru kueri tersebut. Hasil yang masih berjalan dibuang setelah perubahan persetujuan. Untuk menghentikan setiap aksi pada endpoint, cabut izin pengujiannya atau cabut agent; aksi agent dasar lama memiliki izin pengujian terpisah. Administrator dengan izin tulis aset dan pengelolaan pengaturan dapat menggunakan Hapus data terkumpul pada tab Data endpoint aset. Ini menghapus dataset terbaru aset dan membatalkan hasil yang masih berjalan, tanpa menghapus temuan, audit, laporan, atau cadangan. Penghapusan tidak menonaktifkan pemeriksaan antre, berkala mendatang, atau yang diminta manual; nonaktifkan atau cabut izin pengujian sebelum menghapus untuk mencegah pengumpulan kembali. Hapus instalasi agent jika agent tidak boleh lagi menghubungi server.

Catatan persetujuan
Persetujuan mencatat identitas administrator, waktu server, versi dan SHA-256 dokumen, beserta kueri/pack terpilih, tabel, dan versi pack beku. Perubahan dokumen memerlukan persetujuan ulang untuk pemeriksaan yang memerlukan persetujuan eksplisit. Pencabutan dicatat terpisah di log audit. Ini adalah izin pengumpulan operasional, bukan pengganti dasar hukum organisasi atau persetujuan pemilik endpoint.
