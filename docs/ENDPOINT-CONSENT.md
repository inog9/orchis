Endpoint data collection consent
Version 2026-11-08.1

Purpose and timing
Map the software installed on enrolled endpoints to known vulnerabilities (DefenseBot) and report a short list of hardening gaps. Collection runs only after an agent enrolls, its asset is authorised for testing, and an authorised user starts a DefenseBot run (or an administrator explicitly turns on periodic collection). Every named osquery check requires explicit approval of this current document. Enrollment alone does not grant testing or collection permission. Supported queries are preselected in the approval dialog; the administrator can remove any before accepting. High-sensitivity checks and official packs require settings-management permission. Pinned osquery artifacts exist for Linux amd64 and for macOS (Intel and Apple Silicon); macOS support is experimental and only the checks marked for macOS run there. Windows is not supported yet.

Data read
The selected check lists the exact tables and columns before approval. For DefenseBot the data is: operating system release; names, versions and architectures of installed applications and services (deb and rpm packages that are not libraries, kernel or development packages, global npm packages, and on macOS applications and Homebrew packages); listening ports with the program name, program path and owning package; a firewall status summary; and a few kernel and disk-encryption settings. Local account lists, user files, command lines, process environment, browser data, private SSH keys and file contents are not collected. Pack queries not approved for this release stay skipped. Queries needing more privileges are skipped with an explicit reason when the agent lacks them. Reported networks are proposals, not permission to scan.

External vulnerability services
To find known vulnerabilities, the DefenseBot worker sends software names, versions and the package ecosystem (for example the distribution release) to public vulnerability data services such as OSV (osv.dev), and downloads CISA Known Exploited Vulnerabilities and FIRST EPSS data. Host names, IP addresses, accounts and file contents are never sent. Names and versions of installed software can reveal which products an organisation runs; do not approve collection if that is not acceptable. Responses are cached and the data timestamps are recorded in each report. This approval does not enable an external AI provider.

Storage, reports and access
The server treats agent data as untrusted, keeps only known columns, redacts credential-shaped text, limits cells and rows, and bounds each sanitized dataset to 1 MiB. Free-form output and agent-supplied findings/logs are discarded for osquery. The latest successful dataset of each check is stored internally as input for vulnerability matching; it is not shown as an inventory in the console. A failed attempt preserves that earlier dataset and records the failure. Users with finding-read permission see the mapped findings, and report exports follow their own permissions. Administrators and authorised infrastructure operators can also access their managed storage and backups. Only approved mapping rules produce report findings. This approval does not enable an external AI provider.

Retention
The server keeps only the latest successful dataset, until replacement, explicit deletion, or scheduled age-based expiry (default 30 days after server-recorded successful collection). Failed attempts do not extend that lifetime. An administrator can change retention from 1 to 3,650 days; there is no collection history. Findings (default 180 days after last observation), scan results (90 days after completion), frozen PDF/JSON reports (180 days after creation), and audit events (365 days, minimum 90) have separate policies. Scheduled cleanup removes application records and queues exact MinIO and Elasticsearch artifacts for durable deletion, retrying after outages or restart. Deleting an organisation removes its agents and related data; deletion is not complete in external storage while cleanup remains pending. Existing encrypted backups retain their copies until those backups expire. Deleting a latest endpoint dataset alone does not delete findings, reports, audit events or backups. Do not approve collection if the configured retention and backup lifetimes do not meet the organisation's policy.

Stop and delete
Turn off a named check in the endpoint collection settings of the organisation to stop new collections of that query. In-flight results are discarded after approval changes. To stop every action on an endpoint, revoke its testing authorisation or revoke the agent. An administrator with asset-write and settings-management permission can use Delete collected data on the asset's endpoint tab. That deletes the latest datasets for the asset and invalidates in-flight results, without deleting findings, audit events, reports or backup copies. Deletion does not disable queued or future runs; revoke testing permission before deletion to prevent recollection. Uninstall the agent if it should no longer contact the server.

Approval record
Approving records the administrator's identity, server time, document version and SHA-256, along with the selected queries and their tables. A changed document requires renewed approval for checks that need explicit consent. Revocation is recorded separately in the audit log. This is an operational collection permission, not a substitute for the organisation's legal basis or endpoint-owner agreement.

Persetujuan pengumpulan data endpoint
Versi 2026-11-08.1

Tujuan dan waktu
Petakan perangkat lunak yang terpasang di endpoint terdaftar ke kerentanan yang sudah dikenal (DefenseBot) dan laporkan daftar singkat celah hardening. Pengumpulan hanya berjalan setelah agent terdaftar, asetnya diizinkan untuk diuji, dan pengguna berizin memulai DefenseBot (atau administrator secara eksplisit mengaktifkan pengumpulan berkala). Setiap pemeriksaan osquery bernama memerlukan persetujuan eksplisit atas dokumen yang berlaku ini. Pendaftaran saja tidak memberikan izin pengujian atau pengumpulan. Kueri yang didukung dipilih sebelumnya dalam dialog persetujuan; administrator dapat membatalkan pilihan sebelum menerima. Pemeriksaan sensitif dan pack resmi memerlukan izin pengelolaan pengaturan. Artefak osquery yang dipatok tersedia untuk Linux amd64 dan macOS (Intel dan Apple Silicon); dukungan macOS masih eksperimental dan hanya pemeriksaan yang ditandai untuk macOS yang berjalan di sana. Windows belum didukung.

Data yang dibaca
Pemeriksaan terpilih mencantumkan tabel dan kolom yang tepat sebelum persetujuan. Untuk DefenseBot datanya adalah: rilis sistem operasi; nama, versi, dan arsitektur aplikasi dan layanan terpasang (paket deb dan rpm yang bukan pustaka, kernel, atau paket pengembangan, paket npm global, serta di macOS aplikasi dan paket Homebrew); port yang mendengarkan beserta nama program, lokasi program, dan paket pemiliknya; ringkasan status firewall; dan beberapa pengaturan kernel serta enkripsi disk. Daftar akun lokal, berkas pengguna, baris perintah, environment proses, data peramban, kunci SSH privat, dan isi berkas tidak dikumpulkan. Kueri pack yang tidak disetujui untuk rilis ini tetap dilewati. Kueri yang memerlukan hak lebih tinggi dilewati dengan alasan eksplisit bila agent tidak memilikinya. Jaringan yang dilaporkan hanyalah usulan, bukan izin untuk memindai.

Layanan kerentanan eksternal
Untuk menemukan kerentanan yang sudah dikenal, worker DefenseBot mengirim nama perangkat lunak, versi, dan ekosistem paket (misalnya rilis distribusi) ke layanan data kerentanan publik seperti OSV (osv.dev), serta mengunduh data CISA Known Exploited Vulnerabilities dan FIRST EPSS. Nama host, alamat IP, akun, dan isi berkas tidak pernah dikirim. Nama dan versi perangkat lunak dapat menunjukkan produk apa yang dipakai sebuah organisasi; jangan setujui pengumpulan bila hal itu tidak dapat diterima. Respons disimpan sementara dan waktu data dicatat di setiap laporan. Persetujuan ini tidak mengaktifkan penyedia AI eksternal.

Penyimpanan, laporan, dan akses
Server memperlakukan data agent sebagai data tak tepercaya, hanya menyimpan kolom yang dikenal, menyunting teks menyerupai kredensial, membatasi sel dan baris, serta membatasi setiap dataset yang sudah disanitasi hingga 1 MiB. Keluaran bebas dan temuan atau log yang dikirim agent dibuang untuk osquery. Dataset sukses terbaru dari tiap pemeriksaan disimpan secara internal sebagai masukan pencocokan kerentanan; data itu tidak ditampilkan sebagai inventaris di konsol. Percobaan yang gagal mempertahankan dataset sebelumnya dan mencatat kegagalannya. Pengguna dengan izin membaca temuan melihat temuan hasil pemetaan, dan ekspor laporan mengikuti izinnya sendiri. Administrator dan operator infrastruktur berizin juga dapat mengakses penyimpanan terkelola dan cadangan. Hanya aturan pemetaan yang disetujui yang menghasilkan temuan laporan. Persetujuan ini tidak mengaktifkan penyedia AI eksternal.

Retensi
Server hanya menyimpan dataset sukses terbaru sampai diganti, dihapus secara eksplisit, atau kedaluwarsa menurut umur terjadwal (default 30 hari setelah pengumpulan sukses yang dicatat server). Percobaan gagal tidak memperpanjang masa itu. Administrator dapat mengubah retensi dari 1 sampai 3.650 hari; tidak ada riwayat pengumpulan. Temuan (default 180 hari setelah pengamatan terakhir), hasil scan (90 hari setelah selesai), laporan PDF/JSON beku (180 hari setelah dibuat), dan peristiwa audit (365 hari, minimum 90) memiliki kebijakan sendiri. Pembersihan terjadwal menghapus catatan aplikasi dan mengantrekan artefak MinIO dan Elasticsearch yang tepat untuk dihapus secara tahan lama, dengan percobaan ulang setelah gangguan atau restart. Menghapus organisasi menghapus agent dan data terkaitnya; penghapusan belum selesai di penyimpanan eksternal selama pembersihan masih tertunda. Cadangan terenkripsi yang ada menyimpan salinannya sampai cadangan itu kedaluwarsa. Menghapus dataset endpoint terbaru saja tidak menghapus temuan, laporan, peristiwa audit, atau cadangan. Jangan setujui pengumpulan bila retensi dan masa cadangan yang dikonfigurasi tidak memenuhi kebijakan organisasi.

Menghentikan dan menghapus
Nonaktifkan pemeriksaan bernama pada pengaturan pengumpulan endpoint di organisasi untuk menghentikan pengumpulan baru kueri tersebut. Hasil yang masih berjalan dibuang setelah persetujuan berubah. Untuk menghentikan semua aksi pada sebuah endpoint, cabut izin pengujiannya atau cabut agent-nya. Administrator dengan izin menulis aset dan mengelola pengaturan dapat memakai Hapus data terkumpul pada tab endpoint aset. Itu menghapus dataset terbaru aset dan membatalkan hasil yang sedang berjalan, tanpa menghapus temuan, peristiwa audit, laporan, atau salinan cadangan. Penghapusan tidak menonaktifkan proses yang sudah antre atau yang akan datang; cabut izin pengujian sebelum menghapus agar tidak terkumpul ulang. Copot agent bila tidak boleh lagi menghubungi server.

Catatan persetujuan
Persetujuan mencatat identitas administrator, waktu server, versi dan SHA-256 dokumen, beserta kueri terpilih dan tabelnya. Perubahan dokumen memerlukan persetujuan ulang untuk pemeriksaan yang membutuhkan persetujuan eksplisit. Pencabutan dicatat terpisah di log audit. Ini adalah izin operasional pengumpulan, bukan pengganti dasar hukum organisasi atau persetujuan pemilik endpoint.
